# Сообщения, статистика и ежедневные отчёты Threads

Установлено 23.10.2026 по прямому поручению владельца. Работает на действующем VPS рядом с Ивой, без второго браузера, отдельного Telegram polling и финансовых записей.

Перед новым циклом любой кампании `threads_hourly.step` вызывает `threads_inbox.check`. Общий интервал подавления повторных проверок — 60 секунд: одновременные задания двух кампаний не дублируют уведомления. Проверяются Messages, Requests и Hidden. Разговоры не открываются, ответы и принятие запросов не выполняются. Возвращается исходная страница. Это не постоянное соединение: обнаружение происходит при ближайшем обходе, очередь MAX и недоступность Threads могут задержать его.

Курсор диалогов, unread и SHA256 отпечатка превью хранятся в общей alerts.sqlite3, таблица inbox_seen. Текст сообщений не сохраняется, не передаётся AI и не включается в Telegram. Новые unread/изменение превью при unread создают уведомление с именем и ссылкой. Исходящие с явным You:/Вы: не уведомляют. Первый запуск сообщает о видимых непрочитанных; прочитанная история не считается новой. Кнопочные строки без собственного URL ведут в соответствующую папку. Одинаковые имена таких строк и одинаковый текст без стабильной даты могут ограничивать распознавание; разметка и реальные входящие требуют живой проверки. При нераспознанной разметке — ошибка проверки, а не доказательство пустого inbox. Результат ограничен видимыми строками (до 100 на папку), диалоги не прокручиваются для полной исторической выгрузки.

Признаки unread: доступная метка или маленькая синяя точка в строке; для временных подписей используется исходная дата time[datetime], когда доступна. Нужно проверить первый реальный входящий и уведомление до утверждения о полной проверке этого пути. Пустые папки подтверждают только доступ и успешный разбор пустого состояния.

Оповещение записывается в устойчивый outbox с прежними гарантиями: подтверждение Telegram обязательно, неоднозначную доставку не повторять. Внутренний фиксированный запрос threads-notify к root coordinator запускает только threads-monitor.service. Минутный таймер остаётся резервом. Никакого произвольного запуска shell этот запрос не предоставляет. Создатели сообщений/отчётов используют Monitor(recover=False), чтобы не менять отправку, уже выполняемую независимым монитором.

Статистика обновляется монитором примерно раз в минуту из SQLite обеих кампаний, без AI. browser_control status возвращает threads_statistics (today/all, confirmed/uncertain/sending/error_cycles, разбивка кампаний, последние permalink) и threads_messages (время и результат последней проверки). sent без собственного permalink считается uncertain. Исторический пилот без надёжной даты хранится отдельно legacy_confirmed_without_timestamp; lifetime_confirmed_including_legacy включает его, дневные счётчики — нет. Ошибки обходов не означают, что каждый такой обход пытался отправить комментарий; пустой успешный поиск не ошибка. По старым счётчикам нельзя утверждать, что текущая отправка подтверждена или что всё исправно.

threads-daily-report.timer: ежедневно 21:00 Asia/Yekaterinburg, Persistent=true. threads-daily-report.service ставит в outbox одну сводку предыдущих 24 часов (вчера 21:00 — сегодня 21:00), отдельно расширение/поиск заказов, подтверждения/неопределённые попытки/отправка/ошибки обходов и активные предупреждения. Устойчивый id daily:YYYY-MM-DD исключает дубли при повторном запуске. При длительном простое отчёт формируется за последний срок, не за все пропущенные дни. Пауза публикаций не выключает отчётность. Время выбрано по умолчанию; владелец может изменить его.

Установка: deploy/install_threads_reporting.py. Тесты: tests/test_threads_reporting.py плюс существующие hourly/alerts/development/browser_turns. RPC inbox — только ограниченное чтение трёх папок с возвратом агрегата, без текста личной переписки.
