# Скриншоты финансовых документов

`local_finance/financial_screens.py` расширяет прежнее извлечение:

- `page_extractions` сохраняет каждую страницу с видимым числом блоков, всеми
  строками, обрезанными краями, исходным написанием дат/сумм и вопросами.
- `summary_fields` сохраняет подписанные общие сведения: основной долг, проценты,
  итог, ставку, срок и прочие условия отдельно от строк платежей. Их область
  действия (`entire_schedule/remaining/unknown`) не заменяет дату текущего долга.
- `rows` собирается из перекрывающихся последовательностей. Для дат без года
  нужны минимум две соседние строки и совпадение компонентов хотя бы в одной.
  Неполный край дополняется из перекрытия. Одинаковая сумма сама по себе не дубль;
  одинаковые строки внутри одной страницы не удаляются. Наблюдения и ссылки на
  все исходные строки остаются доступны даже после объединения.
- `arithmetic_checks` сверяет итоги с компонентами видимых строк. Несовпадение
  выявляет пропуски, лишние строки или неясную область итога. Сумма строк не
  объявляется текущим остатком долга.

Невидимый год не берётся из даты получения. Для него `date=null`, исходное
«20 октября» остаётся в `date_display`. Подтверждение ISO-даты требует
`date_evidence` с видимым годом. Читаемые суммы сохраняются независимо от года.
Вопросы об обрезанной строке разрешаются, если её данные найдены на перекрытии;
исходные замечания остаются в постраничных наблюдениях.

Новые альбомы, изображения и OCR PDF используют расширенную схему. Точный
детерминированный PDF-парсер Альфы сохранён. Старый неимпортированный OCR графика
при повторном получении перечитывается; предыдущая версия записывается в
`source_document_revisions`. Импортированные банковские графики не переписываются.
Чеки сохраняют прежнюю семантику: график и обзор задолженности не являются оплатой.

## Перепроверка финансовым агентом

`finance_review_document(document_id,pages?)` — внутренний инструмент Sol.
Он находит оригинал по сохранённому идентификатору, проверяет границы каталога
и контрольные суммы, готовит PNG и передаёт их через настоящий image input
следующему шагу модели. Чтение не меняет финансы и не разрешает инструкции с фото.
Пути файлов модель не задаёт. Временные изображения удаляются после задачи.
Поддержаны JPEG/PNG, альбомы и PDF; за проверку прикладываются до 8 выбранных
страниц из документа до 20 страниц. Ответ явно перечисляет приложенные и
оставшиеся страницы: частичная проверка не объявляется полной.

Для нового кредита по скриншотам и сомнений в OCR агент должен вызвать эту
проверку до отказа из-за якобы недоступного изображения. Месяц начала бюджетного
учёта `planning_from_period` не является годом банковского графика: для явно
действующего кредита возможен предварительный текущий бюджет с явной пометкой,
без выдуманной даты выдачи, срока, подтверждения оплаты или точного bank_import.

## Проверка и развёртывание

`tests/test_financial_screens.py` проверяет 17 строк из перекрытий, итоги,
обрезанный край, повтор месяца в разных циклах, неизвестные годы, расхождение
сумм, сохранение исходных наблюдений/версий, границы путей, контрольные суммы
и передачу реальных файлов следующему шагу специалиста.

`deploy/verify_financial_screens.py` читает реальные четыре оригинала Ozon
на VPS, извлекает данные рабочей моделью и проверяет Sol на отдельной копии
SQLite. Пробная запись кредита, если выполняется, остаётся только в этой копии;
повтор задачи должен вернуться из кэша. Рабочий реестр не получает проводок.

`deploy/install_financial_screens.py` проверяет хеши общих исходников и отсутствие
активного пользовательского хода, сохраняет код и SQLite для отката. Меняется
только Python-часть, перезапускаются gateway/Telegram. Движок и тендерный
обработчик остаются работающими. `deploy/repair_screen_extraction.py` исправляет
только ранее неимпортированный источник Ozon, сохраняя старое извлечение и
проверяя неизменность финансовых таблиц. Сам кредит этим скриптом не добавляется.

Артефакты проверки, резервные копии и отчёты:
`data/screen-release-20261021/`.
