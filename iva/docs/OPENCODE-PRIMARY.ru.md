# Первичная обработка через OpenCode

В Telegram `/settings` и постоянные кнопки «⚡ OpenCode» / «🧠 Codex / Luna»
выбирают обработчик новых сообщений. Доступны `/engine opencode`, `/engine codex`,
`/engine` для статуса. Настройка `local_meta.primary_engine` переживает перезапуск.
Управление работает вне модели; сбой OpenCode не мешает вернуться на Codex.
Текстовый/голосовой формат выбирается отдельно и не сбрасывается при переключении.

Режим Codex использует прежний EveBridge и Luna без вызовов OpenCode.
Режим OpenCode — лёгкий первый шаг на **opencode/deepseek-v4.1-flash-free**:
короткие сообщения обрабатываются без тяжёлой Eve-сессии, для рабочего поручения
модель сама пишет содержательный первый отклик и передаёт полный исходный запрос
существующему механизму Eve/Luna с инструментами. Финансовый и тендерный агенты,
их авторизация и модели Sol 6.1 medium Fast сохранены. OCR и проверка оригиналов
финансовых скриншотов не заменяются текстовой моделью DeepSeek.

Первый шаг получает последнее сообщение и до восьми коротких реплик контекста.
Финансы, память, личные факты, интернет, календарь, почта, навыки и документы требуют
существующих инструментов. Вложения и сообщения длиннее 10000 символов нельзя
закрыть прямым ответом модели; полный исходник передаётся рабочему механизму.
Реплики простого диалога остаются в SQLite и daily для штатной памяти. `/new`
ограничивает недавний контекст новой беседой, сохраняя историю и память.

`local_finance/opencode_cli.py` запускает официальный CLI 1.19.3 через loopback
`iva-opencode.service`, чтобы не поднимать новый сервер при каждом сообщении.
В рабочем режиме `opencode_service.py` обращается к локальному API официального
`opencode serve`, сохраняя его штатную обработку и модель. Новый CLI-процесс
на каждую реплику не создаётся. Вариант `iva-fast` отключает глубокое рассуждение
только у первичной модели; ответ проверяется по завершению, фактическому modelID
и структуре JSON. При ошибке/таймауте собственная сессия OpenCode прерывается.
Модель и small_model закреплены на бесплатном варианте; платных подстановок нет.
Отдельные HOME/XDG-каталоги не содержат токенов Telegram, Codex и ключей сервисов.
Сервис слушает 127.0.0.1:18726 с паролем из приватного файла. Автообновления выключены.

Используется штатный build-agent с permission `ask` для всех инструментов.
Его лимит `steps=1` переводит первый и единственный шаг в текстовый режим:
реальная проверка запроса чтения файла получила отказ maximum-steps без native
tool call. Первичной модели нужны только текст и JSON-решение о маршруте.
Адаптер автоматически отклоняет любой native permission request своей сессии
и прерывает её; попытки native tool use также отклоняются. Резервный standalone
`opencode run` никогда не использует `--auto`: такие запросы отклоняет сам CLI.
Это сохраняет штатный OpenCode-harness: конфигурация deny/custom-agent
на текущем free endpoint возвращала ложный 403 «only within OpenCode».

Решения проверяются до передачи рабочего поручения. `local_primary_turns` хранит
источник, состояние, решение, итог и замеры; повтор не запускает рабочие действия.
После начала рабочего механизма его ошибка не вызывает повторное выполнение.
Ошибка/таймаут первичного OpenCode разрешает резервный Codex до запуска инструментов;
60 секунд после сбоя новые сообщения пропускают неработающий первый шаг. Выбранный
режим сохраняется; кнопка повторного выбора OpenCode сбрасывает эту паузу.

Основные файлы: `iva_integration/primary_engine.py`, `local_finance/opencode_cli.py`,
`tests/test_primary_engine.py`. Настройки и binary находятся только на сервере:
`data/opencode-primary.json`, `data/opencode-runtime/`; секреты не входят в исходники.
Проверки и резервная копия релиза: `data/opencode-release-20261021/`.
