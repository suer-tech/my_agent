# Длительное исследование тендеров

Поиск через `tender_agent action=research` создаёт одноразовую задачу в
`data/tender-agent.sqlite3`. Он сразу возвращает ID. Обход выполняет отдельная
служба `iva@research`; диалог и приём Telegram не ждут завершения обхода.
Регулярный мониторинг сам не включается.

## Этапы

1. Последовательно пройти все страницы каждой формулировки из
   `iva_integration/tender_queries.json` (8 семейств: сайты, веб-приложения,
   ИИ/ML, агенты/боты, автоматизация, интеграции, ПО, мобильные приложения).
   Искусственного максимума страницы и количества закупок нет. Конец выдачи
   устанавливается по навигации/счётчику или подтверждённой пустой странице.
   Повтор страницы и нераспознанная выдача — пробел покрытия.
2. Собрать все номера без повторов с происхождением запрос/страница. Сначала
   завершить обход выдачи, затем отбирать по предмету/цене/статусу. Неясные
   карточки направлять на изучение, а не молча исключать.
3. Открыть карточки, вкладки документов и оригиналы. Читать PDF/DOCX/старый
   DOC, XLSX/XLS и ZIP с указанными ограничениями. Полный доступный текст
   разбивается на фрагменты; каждый анализ сохраняется отдельно. До финального
   решения заново читается актуальная карточка.
4. Сопоставить документы, допуск, исполнение, оплату/обеспечение, опыт и
   критерии оценки. Непрочитанные материалы, отсутствие ТЗ/контракта,
   непроверенный тариф/допуск/исполнение блокируют безусловный приоритет.
5. Сохранить полный `report.md` и `manifest.json` в
   `data/tender-research/<ID>/`. В Telegram отправить краткий итог и полный
   файл со всеми решениями, включая отказы и условные варианты. Ограничение
   трёх карточек относится лишь к краткому сообщению, не к полному отбору.

Перед положительным итогом по закупке выполняется отдельный аудит её учёта;
перед финальным отчётом — `tender_coverage_audit.py` по всем запросам/страницам
и номерам, реально показанным ЕИС. Отсутствующая запись или незавершённая
пагинация не позволяют подтвердить полный охват. `manifest.json` сохраняет
результат аудита и его код выхода; пробелы входят в отчёт.

Профиль/диапазон цены берутся из рабочей БД и прямых предпочтений владельца
на момент старта. Значения из внешнего навыка не заменяют рабочий профиль.
Охват означает все страницы сохранённого плана, а не все возможные закупки ЕИС.

## Управление

`tender_agent` принимает `task`, `action`, необязательный `job_id`:

- `research` — запустить; один текущий прямой запрос владельца создаёт одну
  задачу даже при повторном вызове с другой формулировкой.
- `status` — сохранённый прогресс и доступность обработчика.
- `report` — отчёт/путь к полному файлу и состояние доставки. Большие отчёты
  возвращаются в инструменте как явно помеченный фрагмент; файл полный.
- `resume` — продолжить последнюю/указанную задачу и повторить доступ к
  проблемным страницам/файлам, сохраняя пройденные страницы.
- `cancel` — остановить дальнейшую работу; текущий безопасный шаг чтения
  может завершиться, но новая работа/итоговая отправка не запускаются.
- `quick` — прежний короткий вопрос или сохранение предпочтения; его
  ограничение 8 чтений не применяется к research.

Если ID не указан, выбирается последняя задача. Запуск/продолжение/отмена через
gateway требуют текущего прямого сообщения владельца. Диагностические сессии
и документы не авторизуют фоновые задачи. Для изменения предпочтений
используется `quick`, после чего новое исследование получает новый профиль.
Прямые команды `/tenders`, `/tenders_resume [ID]`, `/tenders_cancel [ID]`
обрабатываются транспортом без ожидания нового вызова модели. Обычные просьбы
о статусе, продолжении и остановке также доступны через главную Иву.

## Перезапуск, сбои и доставка

Служба имеет один системный файловый lock. Успех каждого шага фиксируется
SQLite-транзакцией. После перезапуска повторяется максимум одно незавершённое
чтение/вычисление. Временные ошибки повторяются с задержкой; после трёх ошибок
задача приостанавливается с сохранением курсора и уведомлением. CAPTCHA
приостанавливает работу сразу, без обхода проверки. `resume` повторяет шаг.

Исходящая очередь хранится в БД. Неопределённая отправка/перезапуск в момент
отправки получает `uncertain` и автоматически не повторяется. Полный отчёт
остаётся доступен через `report`; состояние доставки видно через `status`.
Задача без сетевых пробелов завершается `completed`; с неполными документами
или страницами — `completed_with_gaps`. Это не подтверждение допуска к торгам.

## Границы

Загрузка одного файла ограничена 8 МБ; распакованный ZIP — 32 МБ и 3 уровня
вложенности. Макросы не исполняются, файлы ZIP не распаковываются на диск.
Сканы PDF без текста требуют OCR, RAR/7z и защищённые файлы помечаются как
непрочитанные. Старый DOC требует системный `antiword`, таблицы — openpyxl/xlrd.
Формулы XLSX читаются как формулы, не выдаются за пересчитанные суммы.
При свободном месте менее 200 МБ задача приостанавливается. Эти ограничения
явно отражаются в отчёте и не превращаются в положительное решение.

Один вызов модели ограничен 150 секундами; общего лимита времени задачи нет.
Общая авторизация CLI сериализована с остальными агентами. Пока работает
очередной вызов Sol, новый запрос модели может ожидать этот общий lock.
Прогресс читается без вызова Sol. Рабочие финансы не меняются.

Резервное копирование включает согласованную SQLite-копию тендерной базы и
каталог оригиналов/отчётов. После установки: `systemctl enable --now iva@research`.
