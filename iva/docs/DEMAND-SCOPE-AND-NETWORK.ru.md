# Границы исследования, исправление цитат и сетевой маршрут

Изменения подготовлены 25 октября 2026. Фактическое развёртывание и результаты
серверных проверок фиксируются отдельно в отчёте установки; этот файл описывает
поведение кода, а не утверждает успешность уже выполненного исследования.

## Один цикл — одно бизнес-направление

В новом цикле сохраняется версия области исследования (`plan.scope`): ПО либо
товары/услуги для продвижения через MAX. Общая задача владельца остаётся в
истории, но не передаётся агентам вместо конкретного поручения. Старые гипотезы
подмешиваются только при явной повторной проверке выбранной гипотезы/вопроса.

Перед поиском отдельный анализ без инструментов проверяет решение оркестратора
и все четыре поручения. Перед запуском проверяются дочерние задания, перед
сохранением — предложенные гипотезы. Отклонённый план получает обратную связь
для ограниченного повтора. Неуместная дочерняя задача становится явным пробелом,
а не отменяет выполненный отчёт. События `scope_*` доступны для диагностики.

Связанные переходы внутри направления разрешены: учёт остатков → интеграция →
отзывы → исправления → сравнение зарубежных решений. Это проверка цели и связи,
не запрет ключевых слов. ПО для продавца хозблоков относится к ПО, продажа самих
хозблоков за комиссию — к торговому направлению. Модельная проверка области
уменьшает риск смешивания, но не доказывает истинность найденного спроса.

Активные старые циклы не перезапускаются и не переписываются. Новый контракт
области действует для новых циклов; история остаётся исходным диагностическим
свидетельством.

## Дословные цитаты для дочерних поручений

Перед допуском поручения действует прежняя строгая проверка источника и цитаты.
Если цитата переведена или не совпадает с исходным текстом, агент получает
исходный текст и запрос исправить только `trigger_quote`/`source_ids`. Вопрос,
методы и критерии проверки менять нельзя. Затем цитата проверяется снова,
включая отдельное решение оркестратора о том, подтверждает ли исправленный
фрагмент тот же смысловой повод. Для синтеза это отдельная сохраняемая проверка:
подлинный фрагмент о другой проблеме не получает допуск автоматически.

Один вызов исправления выполняется за контрольную точку, максимум два на
неизменный запрос. Начало попытки сохраняется до вызова; перезапуск процесса не
обнуляет бюджет. Исходный отчёт сохраняется. Это действует и для поручений из
итогового синтеза. Неподтверждаемое основание становится ограничением отчёта;
родитель не объявляется сломанным только из-за него. Ошибки самого транспорта
модели и поиска продолжают учитываться как технические ошибки.

## Маршрутизация публичных источников

Основное чтение остаётся прямым. По прямому поручению владельца от 26 октября
обычный HTTP 403 (`access_denied`) вызывает один повтор через существующий VPN
namespace `iva-codex`, даже без сообщения о географическом ограничении.
Прежний повтор при явно распознанном географическом отказе также сохраняется.
Успешный точный домен сохраняется в приватном `data/research-network/routes.json`
на семь дней; неудачная попытка имеет часовой интервал до следующей. Максимум
256 доменов. Это конфигурация маршрута чтения исследования, не изменение
глобальных маршрутов VPS или ключей AmneziaWG.

`iva-research-fetch.service` читает публичные страницы через приватный UNIX-сокет
`/run/iva-research-fetch/fetch.sock`. Root-owned helper находится в
`/usr/local/lib/iva-research-fetch/server.py`. Сервис работает от `iva`, видит
готовый namespace и его DNS, не имеет доступа к `.env`, каталогу данных и home.
HTTP-запросы без cookies/авторизации, только GET, с проверкой публичных IP каждого
перенаправления и прежними ограничениями размера/времени. Процесс не меняет VPN.

Успех повтора после обычного 403 не доказывает геоблокировку. Причина такого
маршрута сохраняется как `http_403`, чтение из его кэша — `cached_http_403`.
Распознанные CAPTCHA/антибот-проверки, требование входа и 429 по-прежнему
не запускают VPN-повтор; отсутствие доступа не заменяется свидетельством.
Если VPN также возвращает отказ, источник остаётся недоступным, а для повторной
VPN-попытки на этом точном хосте действует часовая пауза. Чередования IP,
профилей, авторизации или бесконечных повторов нет.

Журнал `network_route` сохраняет домен, причину, маршрут и результат повтора,
а также отдельные `direct_http_status` и `vpn_http_status`, когда ответ получен.
В кэше сохранены причина выбора VPN и оба HTTP-результата исходной попытки.
Статус исследования показывает доступность reader и число доменов в кэше.
Новые события подчиняются существующей политике хранения материалов; активные
контрольные точки защищены, завершённые старые материалы компактируются.

## Проверка и возврат

Сначала устанавливается код через `deploy/upgrade_demand_research.py`, только
при свободном исследовательском ресурсе. Затем `deploy/install_research_fetch.py`
проверяет SHA установленного кода, текущие маршруты, устанавливает новый reader
и сверяет неизменность маршрутов. VPN не перезапускается. При сбое восстанавливаются
прежние helper/unit. Копии находятся в каталоге выпуска, `before` и `network-before`.

Изолированные серверные проверки: `verify_demand_scope.py` проверяет старый
смешанный план и новый план настоящей моделью; `verify_demand_quote_repair.py`
исправляет настоящую невалидную цитату на копии истории; `verify_demand_network.py`
проверяет живой RPC и повтор через VPN с искусственным исходным геоотказом.
Отчёты явно отделяют реальные чтения от искусственной причины повтора.

Методика источников и первичные ссылки: [DEMAND-OSINT-METHODS.ru.md](DEMAND-OSINT-METHODS.ru.md).
