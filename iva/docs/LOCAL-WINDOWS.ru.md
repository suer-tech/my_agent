# Локальный Windows-запуск через Codex CLI

Актуальный путь без VPS и отдельного LLM API-ключа:

```text
Telegram, один личный чат владельца 412850740
  → Python long-poller и постоянная очередь SQLite
  → Codex CLI exec: существующий ChatGPT login, структурированный JSON
  → разрешённая функция прежнего финансового ядра
  → детерминированный результат или предложение /confirm
  → ответ в тот же Telegram-чат
```

Это **совместимый адаптер**, а не запуск всего Ива на Windows. Проверенный upstream Ива `MODEL_PROVIDER=codex` в `agent/provider.ts` использует `createOpenAI(...).responses(...)` и собственный OAuth-файл; он не вызывает Codex CLI. Поэтому не подменяли его фиктивным CLI-провайдером. Прежний плагин Ива/MCP и вся финансовая база/логика сохранены; локальный адаптер вызывает те же Python-функции напрямую. CRM, vault и остальные функции полного Ива здесь не воспроизводятся.

## Что уже проверено на этом компьютере

- Codex CLI `0.117.0`, Node `24.14.0`, Python `3.14.3`.
- `codex login status` после переопределения несовместимого `service_tier` показывает ChatGPT login. Значения credential-файлов не выводились. Обычная команда старого CLI встречает `service_tier=priority` из пользовательской конфигурации, которую эта версия не понимает; общая конфигурация не менялась.
- Настоящий `codex exec`, не заглушка: русский ответ по схеме, запрос остатков, предложение расхода 100 RUB, отдельное подтверждение, итог 57 000 → 56 900 RUB. Все деньги синтетические во временной базе. Транспорт Telegram в этом прогоне синтетический; настоящие HTTP-запросы Telegram не выполнялись.
- Пройдены 38 тестов ядра и локальной интеграции; команда ниже. Сеть, таймаут/ошибка модели и Telegram-сбои в unit-тестах имитируются.
- Скрытый Windows launcher проверен без токена: фоновый процесс корректно завершился с понятной ошибкой настройки. Работа долгоживущего бота с настоящим токеном ещё не проверена.
- Локальный русский синтез через Windows `System.Speech`: найден `Microsoft Irina Desktop`, создан WAV 22 050 Hz длительностью 6,63 секунды. Это проверка локального TTS, **не автоматический голосовой ответ Telegram**.

## Первый запуск

Откройте PowerShell в `E:\Projects\main_agent`:

```powershell
python -m unittest discover -s tests -v
python -m local_finance.bot --check
```

`--check` делает один реальный запрос к Codex с существующим login и показывает только наличие Telegram-настройки (True/False), без токена. При отсутствии login войдите через обычный `codex login`. Для проверки статуса с установленной сейчас версией CLI можно использовать `codex -c service_tier=fast login status`. Адаптер не требует LLM API key.

Затем сохраните **новый перевыпущенный** Telegram-токен скрытым вводом:

```powershell
.\scripts\Configure-Local.ps1
.\scripts\Start-Local.ps1
```

Скрипт не перезаписывает существующий `.env`. Он сохраняет токен без показа в консоли, ограничивает Windows ACL файлом владельца и SYSTEM и записывает **только `FINANCE_ALLOWED_USER_ID=412850740`**. Если PowerShell блокирует скрипты политикой организации, запуск можно выполнить из разрешённого терминала Python после ручной подготовки `.env`; глобальная ExecutionPolicy автоматически не меняется.

Фоновый процесс запускается с `WindowStyle Hidden`. Для диагностики без фона:

```powershell
.\scripts\Start-Local.ps1 -Foreground
```

Остановка фона:

```powershell
.\scripts\Stop-Local.ps1
```

PID проверяется по времени старта, чтобы не остановить случайный переиспользованный процесс. Остановка завершает дерево, включая активный CLI. Незавершённые отправки/подтверждения после аварии становятся `uncertain` и не выполняются повторно автоматически. При запуске второй копии одной базы действует файловая блокировка.

Первое сообщение боту: `/start`. Для изменения финансов ассистент покажет точные параметры и код. Только отдельное `/confirm CODE` выполняет изменение. `/cancel CODE` отменяет; новая заявка заменяет старое неподтверждённое предложение. Код действует 30 минут. Неясный чек/дата/сумма требуют уточнения; похожая операция требует второго отдельного подтверждения. `/new` очищает историю диалога и предложения, сохраняя реестр.

`.env` не ищется в истории чатов и не включён в Git. В момент подготовки файла нет, настоящий бот не запущен. На токен и user ID мы не ссылаемся через аргументы процессов: токен читается только из локального `.env`, ID фиксирован в конфигурации и проверяется кодом. Изменение ID в `.env` на другой аккаунт блокирует запуск. Вход допускается только когда **и from.id, и private chat.id равны 412850740**; группы и другие пользователи игнорируются.

Если у бота уже включён webhook, запуск откажется его менять. Сначала остановите предыдущий poller/Ива и осознанно уберите webhook. Одновременно Ива и этот адаптер с одним токеном запускать нельзя.

## Конфигурация, данные и гарантии

Пример: `config/local.env.example`. Рабочая база по умолчанию `data/local-finance.sqlite3` — изначально пустая, отдельно от `data/demo.sqlite3`. Изменить её можно только операторским аргументом `python -m local_finance.bot --db <path>`, не сообщением Telegram. `Start-Local.ps1` ограничивает ACL папки `data`.

История и очередь находятся в той же базе (`local_history`, `local_updates`, `local_pending`, `local_meta`), поэтому резервная копия SQLite включает контекст. Ассистент получает последние 12 сообщений и ограниченный снимок фактов; вычислители всегда читают всю базу. CLI работает `--ephemeral`, без глобального `resume --last`: контекст восстанавливается нашим приложением строго для нужного чата. Долгая историческая беседа обрезается; долговременные финансовые факты остаются в реестре.

Очередь сохраняется до продвижения Telegram offset. Обработка последовательна, один CLI-запрос на шаг; максимум четыре шага чтения инструментов. Неопределённая доставка ответа не повторяется автоматически. После аварии нужно сверить чат/`local_updates` и реестр. Новое сообщение продолжает работу; если ответ потерян, можно запросить остатки/историю заново. Это осторожная доставка с ручной сверкой, а не обещание exactly-once через сеть.

Настройки Codex: модель берётся из существующего `config.toml`, либо задаётся `FINANCE_CODEX_MODEL`; сейчас проверена `gpt-6.1-sol`. `FINANCE_CODEX_TIMEOUT=150` секунд на вызов. Нативный `codex.exe` обнаруживается в npm-установке или задаётся оператором через `FINANCE_CODEX_EXE`. `.cmd/.ps1` wrapper через shell не запускается. Сырые stderr и event stream CLI не публикуются в Telegram/логи; ошибки авторизации, лимита и таймаута переводятся в понятные сообщения.

Каждый вызов использует короткоживущий изолированный `CODEX_HOME` под существующей `.codex`: туда копируется только credential-файл действующего CLI-login. Файл не показывается модели, не попадает в проект и удаляется после вызова. Если CLI обновил login, обновление возвращается в исходный auth-файл только если другой процесс за это время его не менял. Существующая пользовательская конфигурация, MCP-серверы, skills, apps и hooks туда не копируются. После жёсткого завершения процесса может остаться каталог `.codex/finance-cli-*`; остановив бот и проверив, что активных его CLI нет, удалите только эти каталоги. Keyring-only login без `auth.json` этой версией адаптера не поддерживается.

CLI получает `--sandbox read-only`, `approval_policy=never`, отключённые shell/app/plugin/multi-agent/JS/image-generation tools и web search. Опасных bypass-флагов нет. Вывод CLI — только JSON-предложение: он не имеет MCP-сервера с правами финансовой записи. Python отдельно проверяет имя функции/аргументы; запись проходит после одноразового подтверждения владельца. Финансовое ядро не предоставляет shell/SQL/платёжных API. Остатки, прогноз и итог кредитного сценария выводятся из Python напрямую, чтобы не отдавать денежную арифметику языковой модели.

## Напоминания на Windows

Пока бот запущен и компьютер бодрствует, встроенная проверка раз в минуту после `FINANCE_REMINDER_HOUR` отправляет события в тот же разрешённый чат. По умолчанию 09:00 Asia/Yekaterinburg (UTC+5). Срок предупреждения по умолчанию **один календарный день до платежа** (`FINANCE_DEFAULT_LEAD_DAYS=1`, `schedule.lead_days=1`); другой срок можно явно задать у отдельного платежа. Например, платёж 20 октября — напоминание с 09:00 19 октября. Интервал проверки остаётся **60 секунд**, а не сутки. Без времени платежа сутки здесь календарные, не точные 24 часа до банковского списания. Состояния отправок и защита от дублей используются из прежнего ядра. После сна/простоя проверка догоняет пропущенные ожидания после местного штатного времени. Сетевой результат `uncertain` требует сверки вручную. Не запускайте параллельно старый `remind.py --send` для той же базы; механизм захвата общий, но отдельный адресат/настройки могут отличаться.

Автозапуск Windows/Task Scheduler не установлен; после перезагрузки запустите `Start-Local.ps1`. VPS/SSH для этого не нужны. Бэкап прежним `server.py --backup` работает и с `data/local-finance.sqlite3`; не копируйте голый файл при активном WAL. Подробности в `SETUP.ru.md`, но её Linux/systemd-часть относится только к будущему VPS.

## Голос и чеки отдельно от CLI

`codex exec --help` этой версии поддерживает `--image`, но реальный чек и извлечение ИТОГА ещё не испытаны. Текущий Telegram-адаптер принимает **только текст**, на фото/голос отвечает об отсутствии подключения и не создаёт финансовых записей. Штатный STT/vision Ива к нему автоматически не переносится.

Локального Whisper/whisper.cpp/faster-whisper и ffmpeg в PATH не найдено. Проверенный путь для офлайн-STT — [whisper.cpp](https://github.com/ggml-org/whisper.cpp): Windows поддерживается, для русского нужен многоязычный файл модели, а не `.en`; Telegram OGG требуется преобразовать в PCM WAV 16 kHz mono. Движок, модель и конвертер здесь не скачивались/не устанавливались. Для будущего контура нужно добавить безопасную загрузку вложения, локальное STT/OCR, показ транскрипции/ИТОГА и то же подтверждение операции.

Русский локальный TTS уже можно проверить без API:

```powershell
python scripts/test_windows_voice.py
```

Это обёртка для надёжного UTF-8 в Windows PowerShell 5.1. `Speak-Local.ps1` принимает текст через stdin, выбирает установленный ru-RU голос и создаёт WAV. Автоматическое озвучивание Telegram потребует преобразования в OGG/Opus (конвертер не найден) и подключения прежнего `voice_reply.py`/outbound hook. Пока не обещаем, что бот слышит или отвечает голосом.

## Воспроизвести реальные и имитированные проверки

```powershell
python -m unittest discover -s tests -v
python scripts/smoke_local_cli.py
```

Вторая команда тратит обычные запросы подписки Codex, использует синтетическую временную базу и фальшивый Telegram transport. Проверяет реальный CLI и финансовую арифметику, обязательное подтверждение, дубль update, восстановление контекста и ограничение владельца. Она не читает `.env` и не отправляет сообщения в Telegram.

Официальная документация: [неинтерактивный Codex](https://learn.chatgpt.com/docs/non-interactive-mode), [CLI reference](https://learn.chatgpt.com/docs/cli/reference). Фактически использованные флаги дополнительно проверены локальной справкой `codex exec --help`: новая онлайн-документация описывает и параметры, которых ещё нет в установленной 0.117.0; они в адаптер не включены.
