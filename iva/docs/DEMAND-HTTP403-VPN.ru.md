# Повтор HTTP 403 через VPN

По поручению владельца от 26 октября 2026 обычный HTTP 403 теперь допускает
одну повторную попытку чтения публичной страницы через существующий VPN.
Это заменяет прежнее правило «повторять только явно распознанный географический
отказ». Признаки географического отказа по-прежнему обрабатываются отдельно;
успешный повтор обычного 403 не объявляется доказанной геоблокировкой.

## Поведение

1. Публичный сборщик выполняет обычный прямой запрос.
2. Если результат — целочисленный HTTP 403 и категория `access_denied`, тот же
   публичный адрес, включая безопасно проверенное перенаправление, один раз
   читается через `iva-research-fetch.service` в namespace `iva-codex`.
3. Успешный маршрут запоминается для точного хоста на семь дней. Поддомены
   автоматически не включаются. Старый географический кэш читается без миграции.
4. При повторном отказе источник остаётся недоступным. Следующая VPN-попытка
   для этого хоста допускается через час; внутри текущего чтения цикла нет.

Распознанные CAPTCHA/антибот-проверки, требования входа и HTTP 429 не запускают
повтор. Проверка публичных адресов, TLS, перенаправлений, размеров и времени
чтения сохранена. Ни cookies, ни аккаунты, ни интерактивный браузер не используются.
Ключи VPN, глобальные маршруты, сетевые службы и привилегированный reader
не перенастраиваются.

## Журнал

В `network_route` фиксируются `route`, `reason`, `host`, `retry`, `route_saved`,
`direct_error`, отдельные `direct_http_status` и `vpn_http_status`.
Допускаются только целочисленные HTTP-статусы 100–599; произвольные диагностические
данные, ключи и тела страниц отказа не включаются. Если VPN недоступен либо
действует cooldown, причина пропущенного повтора тоже видна.

Причина обычного повтора — `http_403`, последующего чтения через успешный кэш —
`cached_http_403`. Прежние `explicit_geographic_restriction` и
`cached_geographic_restriction` сохраняют свой смысл. Состояние кэша содержит
причину маршрута и исходные HTTP-результаты. Статус Ивы показывает политику
`http_403_or_explicit_geo`.

## Развёртывание и приёмка

Выпуск: `/opt/iva/data/demand-http403-release-20261026`.
Установщик `deploy/install_demand_403.py` использует прежние проверенные
блокировки, допуск только в простое, резервные копии, контрольные суммы и
краткую остановку scheduler. Расписание исследования остаётся на паузе;
старые завершённые циклы и их неудачные чтения не переписываются.

`deploy/verify_demand_403.py` выполняет **настоящий прямой запрос** к обсуждению
UKBusinessForums и условный настоящий VPN-повтор по результату. HTTP 403 в этой
проверке не подставляется искусственно. Используется отдельный кэш маршрутов и
обычное разрешение координатора на исследование; модели, рабочая исследовательская
база, финансы и уведомления не задействуются.

Успех проверки механизма и доступность страницы учитываются отдельно. Если
через VPN снова получен отказ, механизм может пройти проверку, но документ
не считается прочитанным. Если прямой запрос уже успешен либо возвращает
иную категорию, это не выдаётся за живое доказательство повтора после 403.

Результаты: `installation.json`, `tests.log`, `verification-network/report.json`
и `final-verification.json` внутри каталога выпуска. Старые доказательства
предшествующих выпусков остаются историческими и не подменяются новыми.

### Фактическая проверка 26 октября

Установлены шесть файлов; **235 серверных тестов в 12 наборах прошли**, включая
настоящие проверки UNIX-сокетов. Живой тест прошёл **10 из 10 условий**:
UKBusinessForums напрямую вернул HTTP 403 `access_denied`; автоматический
VPN-запрос получил HTTP 307, после чего проверка адреса перенаправления завершилась
`disallowed_url`. Страница не прочитана, подтверждённого текста нет. Механизм
повтора проверен, успешный доступ к этому форуму через VPN не подтверждён.

Отдельная ограниченная диагностика сделала ровно один запрос через VPN:
HTTPS-переход на тот же хост отклонён штатной проверкой из-за параметра `sig`
(`session_parameter`). Значения параметров не сохранялись, переход не выполнялся;
проверки сессионных и подписанных адресов не ослаблялись.

Действующий gateway держал старый модуль в памяти. На свободной границе Telegram
был штатно приостановлен, gateway перезапущен существующим проверенным helper,
активность Telegram восстановлена. Короткая SQLite-блокировка не удерживалась
во время ожидания завершения long poll. Авторизованный запрос к рабочему
инструменту Ивы подтвердил новую политику `http_403_or_explicit_geo`.

После проверки совпали 40 контрольных сумм исходников; все таблицы рабочей
исследовательской базы, финансовые операции, спецификации расписаний и выбранный
движок остались прежними. Хеши маршрутов хоста/VPN, root-owned helper и unit не
изменились. Восемь основных служб активны, исследовательский ресурс освобождён,
регулярное исследование остаётся на паузе. Рабочий кэш маршрутов диагностикой
не изменялся.
