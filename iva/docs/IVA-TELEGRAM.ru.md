# Ива в Telegram

Подключение19октября2026: Telegram принимает `local_finance.iva_telegram`, а разговор ведёт настоящий движок Iva/Eve через SDK с долговечной sessionId и Codex CLI. Старый финансовый чат-цикл не отвечает вместо Ива: его класс используется только для подтверждаемых операций реестра и прежнего проверенного чтения документов.

Единая рабочая база — `E:/Projects/main_agent/data/local-finance.sqlite3`. Маршрут задан в `data/iva-runtime.json`. Предыдущая `data/iva-pilot/finance/finance.sqlite3` сохранена как архив и запрещена для записи через Ledger; gateway/MCP читают и изменяют рабочую базу. Различавшиеся служебные ID общего счёта перед подключением сопоставлены по смыслу. Все семь долгов, исходные18строк, доходы/расходы и документы сохранены. Фактические денежные операции переключение не создаёт.

Диалог: текст → долговечная очередь Telegram → Iva/Eve → инструменты/память → ответ Telegram. Голос: сохранённый оригинал → локальный whisper.cpp → та же Iva → текст и Cartesia Tatiana/OGG Opus. `/voice auto` отвечает голосом на голос, `/voice on` озвучивает все ответы, `/voice off` оставляет текст. Ошибка TTS сохраняет текст. Распознанная речь и вложения не исполняют `/confirm`.

PDF/TXT/фото/альбомы используют прежний приёмник оригиналов с SHA256, подписями и всеми страницами. Извлечение передаёт данные Ива; банковский импорт готовит предложение с подтверждением. Для продолжения доступны document_context и conversation_context. Сохранённый один альбом обрабатывается одним запросом, а исходные участники и подписи остаются в базе и манифесте. Повторный файл/источник не создаёт второй расход или график.

Доступ только для согласованного владельца в личном чате. Текстовые `/confirm CODE` и `/cancel CODE` обрабатываются вне модели; callback допускается только от того же владельца в том же личном чате. Финансовый инструмент модели имеет read/propose/pending и не имеет полномочия подтверждать. Секреты не передаются дочернему Iva-клиенту; Telegram-токен загружается из прежнего локального.env в транспорт. Cartesia-ключ остаётся в отдельном защищённом файле.

Команды владельца: `/help`, `/pending`, `/confirm CODE`, `/cancel CODE`, `/new`, `/voice auto|on|off`, `/retryvoice ID`, `/recover ID`. `/new` меняет диалог, не стирает память и предложения. `/recover` возвращает сохранённый завершённый ответ без повторного исполнения. Прерванный или не подтверждённый ход/отправка получают uncertain и не воспроизводятся вслепую; нужны просмотр pending и сверка факта. Ошибка перед завершением хода не отменяет уже подготовленные предложения.

Управление в PowerShell:

```powershell
.\scripts\Start-Iva.ps1
.\scripts\Status-Iva.ps1
.\scripts\Stop-Iva.ps1
```

Старт скрытый, без окон. Установлен автозапуск `Iva Telegram.lnk` при входе текущего пользователя; supervisor восстанавливает завершившийся транспорт и локальные сервисы. Проверка PID включает фактическую команду и время создания, а не только файл PID. Второй запуск не создаёт второй poller; старый `local_finance.bot` отключён, Start/Stop-Local направляются на новые команды. Транспорт держит прежнюю блокировку рабочей базы. Остановка перестаёт принимать новые сообщения и даёт уже принятому ходу закончиться. Память и её04:00-планировщик при Stop-Iva остаются включены.

Windows должен работать с выполненным входом пользователя; это не системная служба и не VPS. Полный перезапуск/вход Windows ещё не наблюдался. Очередь, sessionId, курсор Eve и результаты ходов сохраняются на диске. Повтор источника получает готовый ответ из кеша без второго вызова модели. SDK-сессия переиспользуется между отдельными Node-процессами; длительно неактивный диалог начинает новую сессию с той же памятью.

Финансовые уведомления отправляет один транспорт по штатным occurrence/state за день, с09:00 Asia/Yekaterinburg. Состояния прежних отправок сохранены. Ожидавшее до подключения уведомление с уже прошедшей датой поставлено в held_at_cutover, без внезапного повтора. Старые входящие до границы подключения сохраняются как held_before_cutover. Подтверждённая просрочка остаётся в финансовом прогнозе; неизвестное исполнение не превращается в просрочку. Общие уведомления Ива не дублируют финансовые.

Память — прежний `data/iva-pilot/app/vault`, native night.ts,04:00 Екатеринбурга, скрытый autostart. CORE ссылается на инструмент для актуального перечня долгов и сумм, не содержит текущую денежную истину. Штатные tool/CLI ограничения сохранены. Новые Telegram-ходы попадают в daily; исходники более раннего профиля не переписывались.

Резервные копии и сверка: `data/iva-telegram/cutover-backup.json`. Текущий отчёт: `data/iva-telegram/verification.json`, статус: `status.json`, журналы без текстов запросов и секретов: `worker.log`, `supervisor.log`. До первого входящего сообщения владельца фактическую доставку ответа именно в его Telegram нельзя считать проверенной. Инициативное сервисное сообщение не отправляется.
