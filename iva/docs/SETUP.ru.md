# Установка и эксплуатация

Сейчас пользователь выбрал локальный Windows + Codex CLI. Актуальная инструкция — [LOCAL-WINDOWS.ru.md](LOCAL-WINDOWS.ru.md). VPS не требуется; Linux/systemd ниже сохранены для возможного переноса позднее.

## Локальная проверка

Python 3.11+ (локально проверено на Python 3.14.3). Финансовое ядро не требует pip/npm. На Linux необходима системная база часовых поясов `tzdata`; на Windows для worker может понадобиться Python-пакет tzdata либо явный `--today`. Из корня:

```text
python -m unittest discover -s tests -v
python examples/demo.py
python plugin/family-finance/remind.py --db data/demo.sqlite3 --today 2026-10-19
```

Без `--send` worker ничего не отправляет. Не используйте демо-базу при настройке реальных напоминаний.

## VPS и Ива

Предполагается Linux с systemd user services, отдельный пользователь без root для приложения. Сначала установите Ива по официальной инструкции, проверьте версии и `iva doctor`. Не исполняйте обновлённый upstream вслепую: зафиксированный нами commit указан в `IVA-INTEGRATION.ru.md`. Текущая серверная установка ещё не выполнялась.

Перенесите этот проект в `~/main_agent`, Ива ниже условно установлена в `~/iva`. Если путь другой, замените его во всех командах и unit-файле. В мастере Ива задайте Telegram bot token и одного владельца (`TELEGRAM_ALLOWED_USER_IDS`); используйте один личный чат. В BotFather запретите добавлять этого бота в группы. Для worker `FINANCE_CHAT_ID` — ID этого же личного чата. Личный user ID и chat ID здесь обычно совпадают, но проверьте полученный Telegram update. Токен и API-ключи не присылайте в Git/отчёт.

Настройте LLM с vision; для русской речи `DEEPGRAM_API_KEY`, при желании `DEEPGRAM_LANGUAGE=ru`. Эти параметры принадлежат Ива. Финансовый MCP получает только путь собственной базы.

Интерактивно на сервере:

```bash
cd ~/main_agent
python3 -m unittest discover -s tests -v
iva plugin add ./plugin/family-finance --trust
iva plugin list
iva doctor
```

Upstream устанавливает MCP proxy и пересобирает соединения. `--trust` разрешает запуск локального кода плагина на VPS; используйте после проверки файлов. Если команда запускается самой Ива в неинтерактивном режиме, upstream требует `iva plugin propose <folder>` и подтверждение в Telegram. Это не делалось локально без доступа.

Плагин копируется в store. Рабочая БД: `~/iva/data/plugin-data/family-finance/finance.sqlite3`; её создаёт MCP при старте. **Не переносить туда `data/demo.sqlite3`.** После изменения исходного плагина выполняйте `iva plugin update family-finance`; сам MCP-процесс не читает живые файлы проекта.

Сначала попросите Ива создать счета с остатками на конец одной даты, затем резерв/дневной бюджет, планы доходов и обязательств, условия кредитов и соответствующие платежи. Сверьте исходные остатки с банковскими приложениями. Вызовите прогноз до конца текущего и следующего месяца.

## Напоминания

Отдельный worker использует тот же токен только для исходящих сообщений. Не запускает getUpdates, не мешает единственному poller Ива. Создайте вручную `~/.config/family-finance/worker.env` из `config/finance.env.example`, задайте токен и фиксированный chat ID, права 0600. Папки с финансовой базой и резервами — 0700; доступ к базе только пользователю сервиса (0600). Первый запуск приложения/создание копии выполняйте с `umask 077`.

```bash
umask 077
python3 plugin/family-finance/remind.py --db ~/iva/data/plugin-data/family-finance/finance.sqlite3
# После сверки текста и получателя — реальная отправка:
set -a
. ~/.config/family-finance/worker.env
set +a
python3 plugin/family-finance/remind.py --db ~/iva/data/plugin-data/family-finance/finance.sqlite3 --send
```

Для автоматизации проверьте пути в `deploy/family-finance-reminders.service`, скопируйте оба unit-файла в `~/.config/systemd/user/` и выполните:

```bash
systemctl --user daemon-reload
systemctl --user enable --now family-finance-reminders.timer
systemctl --user list-timers
```

Timer проверяет напоминания ежедневно в 09:00 Asia/Yekaterinburg. Можно изменить OnCalendar; для службы после logout администратор включает linger пользователю. `lead_days` задаётся у каждого платежа/дохода (0..365), разрыв до зарплаты виден в прогнозе. Автоматических предупреждений именно по прогнозному разрыву пока нет — worker напоминает события. Текст reminder относится к неподтверждённому ожиданию: факт оплаты/дохода надо связать через occurrence.

Повторный запуск не повторяет успешно отправленное. Пропущенные при простое события догоняются, включая просроченные. При неопределённом результате сети состояние `uncertain`, при аварии после захвата — `sending`: автоматического повтора нет, чтобы не спамить. Проверяйте `journalctl --user -u family-finance-reminders.service` и таблицу `reminders`. После сверки с чатом оператор может перевести конкретную запись в `sent` либо `pending` через sqlite3. Отменённые/подтверждённые ожидания снимаются с pending при следующем запуске. Абсолютная exactly-once доставка при сбое Telegram не обещается.

## Голосовые ответы

В Ива найден STT, готового исходящего TTS не найдено. Наш `voice_reply.py` — отдельная точка подключения. Выберите локальный или облачный TTS с русским голосом; создайте операторский adapter, который читает UTF-8 stdin и сохраняет OGG/Opus по `--output`. При WAV/MP3 движке нужен конвертер (например ffmpeg). Укажите argv в `FINANCE_TTS_COMMAND_JSON` (JSON-массив, не shell-строка), в одном элементе `{output}`.

```bash
printf '%s' 'Проверка русского голоса. Минимальный остаток — двадцать тысяч рублей.' | python3 plugin/family-finance/voice_reply.py --output /tmp/finance-test.ogg
# Только после прослушивания и сверки чата:
printf '%s' 'Напоминание об обязательном платеже.' | python3 plugin/family-finance/voice_reply.py --send
```

Это путь интеграции, не установленный TTS-сервис. Финансовый MCP не запускает произвольные команды. Для автоматического озвучивания ответов нужен отдельный доверенный outbound hook Ива, вызывающий этот адаптер; пока ответы в чате текстовые. До выбора TTS не заявлять пользователю, что ответы голосом включены.

## Резервирование и восстановление

Копировать только основной SQLite-файл при активном WAL небезопасно. Используйте SQLite backup API:

```bash
umask 077
mkdir -p ~/finance-backups
python3 ~/main_agent/plugin/family-finance/server.py --db ~/iva/data/plugin-data/family-finance/finance.sqlite3 --backup ~/finance-backups/finance-2026-10-18.sqlite3
```

Существующий файл не перезаписывается. Копия содержит счета, операции, черновики, аудит, правила, настройки, кредиты и состояния отправок. Храните ежедневные/еженедельные копии по своей политике, шифруйте и переносите одну копию за пределы VPS. Исходные вложения и vault Ива резервируются отдельно; токены — отдельно с шифрованием. Расписание бэкапов здесь намеренно не активировано.

Для восстановления остановите timer, worker и MCP unit `iva-mcp-family-finance-ledger.service`; сохраните текущую папку базы в отдельное место; поместите проверенную резервную копию в **новую пустую папку** как `finance.sqlite3`. Нельзя оставлять старые `-wal/-shm` рядом с восстановленной копией. Проверьте `PRAGMA integrity_check`, права 0600 и `snapshot`, затем верните путь службы/данные и запускайте сервисы. Старая копия reminders может повторить отправки, поэтому сверяйте события после даты бэкапа с Telegram. Тест проверяет восстановление балансов из копии; полный drill VPS ещё нужен.

## Приёмка после предоставления доступа

1. Проверить один разрешённый личный чат; посторонний user ID не получает доступ.
2. Прислать текст расхода, русский голос с неясной датой, фото чека со скидкой. До подтверждения баланс не меняется; уточнения обязательны. Повторно доставить тот же update и переслать похожий чек — проверить два вида защиты от дублей.
3. Подтвердить зарплату и кредитный платёж по occurrence, сверить отсутствие двойного счёта; исправить один расход и сверить аудит.
4. Сверить разрыв до зарплаты, резерв/повседневные траты и сценарий покупки на отдельном счёте. Сверить каждую из шести кредитных моделей с договором/банком.
5. Проверить напоминание за заданное число дней и повторный запуск без дубля; отключить сеть и проверить uncertain.
6. Восстановить тестовую копию, сверить остатки. Отдельно проверить голосовой ответ после выбора TTS. Только затем включать автоматические отправки на реальных данных.
