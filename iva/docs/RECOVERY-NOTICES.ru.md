# Уведомления Ивы о подтверждённых исправлениях

Краткое уведомление владельцу отправляется после положительной проверки восстановления. Сообщение объясняет сбой, выполненное действие и проверку. Создание задания Codex, прохождение изолированных тестов или исчезновение ошибки сами по себе не означают исправление.

## Подтверждения

| Процесс | Когда появляется уведомление |
| --- | --- |
| Threads | Задание ремонта получило `verified`, код установлен, тесты прошли, после установки реально проверены входящие, запросы и скрытые запросы. Текущий инцидент закрыт. |
| Почта | После ошибки успешно прочитаны новые письма и продвинут UID при прежнем UIDVALIDITY. Пустой опрос или сброс курсора не подтверждают обработку проблемного письма. |
| Исследование | После технического сбоя цикл действительно завершён без технических ошибок. Отдельно указывается, если успешно завершился следующий цикл, а прежний отчёт не исправлялся. |
| Цитаты | Агент исправил запрос, дословная цитата проверена, оркестратор одобрил запрос, родительское поручение завершено. Это не сообщение о завершении всего исследования. |
| План | Отклонённый план исправлен и прошёл независимую проверку соответствия направлению. |
| OpenCode | Зафиксированы подтверждённый сбой провайдера, выполненный перезапуск и успешные проверки состояния сервиса и доступности провайдера. Это не проверка качества модельного ответа. |

Сборщики читают исходные базы без изменений. Существующие ограничения автоматического ремонта, очереди браузеров, блокировки исследования и запрет повторной отправки неподтверждённых публикаций сохранены.

Для чтения Threads SQLite иногда создаёт служебные WAL/SHM-файлы рядом с базой. Поэтому unit разрешает эти файловые операции в каталоге `threads-browser/repair`, но основной `repair.sqlite3` дополнительно защищён `ReadOnlyPaths`; соединение открывается с `mode=ro`. `immutable=1` применять нельзя: оно игнорирует текущий WAL и может дать устаревшее подтверждение.

## Хранение и доставка

`iva-recovery-notices.timer` запускает обработку каждую минуту. Модели для неё не вызываются. Отдельный `flock` исключает одновременные обработчики. Состояние хранится в `/opt/iva/data/recovery-notices/notices.sqlite3`, краткий снимок — в `status.json`. Статус доступен Иве через `browser_control` → `status.recovery_notices`.

Курсоры сборщиков и новые уведомления фиксируются одной транзакцией. Первая установка создаёт точку отсчёта без рассылки истории, но сохраняет наблюдаемые незавершённые инциденты. Стабильный идентификатор события предотвращает повторные сообщения после перезапуска.

Перед отправкой проверяется транспорт Telegram. Подтверждённое сообщение сохраняет `message_id`. Неопределённый результат отправки получает `uncertain` и автоматически не повторяется. Состояние `sending`, оставшееся после аварии, также становится `uncertain`. За один запуск отправляется максимум одно сообщение. Неотправленные события старше суток истекают; через 90 дней старые тексты и подробности сокращаются, идентификаторы остаются для защиты от повторов. База входит в ежедневную резервную копию.

Сообщения составляются из фиксированных шаблонов без текста переписки, писем, цитат, ключей и необработанных исключений. Повторы попыток остаются в технических журналах. Старый подавленный поток технических Threads-уведомлений не включается.

## OpenCode

Root-helper `/usr/local/lib/iva/opencode_health.py` сохраняет до 32 подтверждённых восстановлений в своём приватном состоянии. Очищенный снимок публикуется атомарно в `/var/lib/iva-opencode-health-events/events.json`: каталог `root:iva 0750`, файл `root:iva 0640`. Ива может читать снимок, но не изменять его. Приватное состояние watchdog не раскрывается. Ошибка экспорта не повторяет перезапуск; следующая проверка повторяет экспорт.

## Проверка и установка

`deploy/install_recovery_notices.py` использует отдельный каталог выпуска, контрольные суммы исходников и текущих файлов, изолированные тесты, резервные копии с правами и откат. Изменения устанавливаются на свободной границе, без прерывания исследования. OpenCode для проверки уведомлений не перезапускается принудительно. Проверка доставки выполняется правдивым сообщением о включении функции; вымышленный инцидент не создаётся.

Для диагностики: `systemctl status iva-recovery-notices.timer`, `journalctl -u iva-recovery-notices.service`, снимок `status.json`. Статус старше трёх минут помечается устаревшим. Не следует удалять очередь, сбрасывать курсоры, переводить `uncertain` обратно в `pending` или подделывать `verified` ради теста доставки.
