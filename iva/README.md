# Семейный финансовый модуль для Ива

Финансовое ядро: Python 3.11+, SQLite, MCP и локальный Telegram-адаптер через Codex CLI. Секретов в исходниках нет; пользовательские данные и вложения — в защищённом data, исключённом из Git.

**Бот @suertech_agent_bot работает локально на Windows; доступ только владельцу 412850740.** Голос с телефона и голосовой ответ подтверждены пользователем. Подключены фото/альбомы, PDF и TXT, постоянный черновик ежемесячных трат и точные банковские графики с подтверждением. [Актуальная инструкция и реальные ограничения](docs/CURRENT-STATUS.ru.md).

```powershell
python -m local_finance.bot --check
.\scripts\Configure-Local.ps1
.\scripts\Start-Local.ps1
# Остановка: .\scripts\Stop-Local.ps1
```

`Configure-Local.ps1` предлагает скрытый ввод нового Telegram-токена. Codex не получает произвольные команды из Telegram: CLI формирует JSON, Python разрешает только финансовые функции. Демо с реальным CLI: `python scripts/smoke_local_cli.py`.

## Проверить за минуту

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
python examples/demo.py
python plugin/family-finance/server.py --db data/demo.sqlite3 --call snapshot
```

Демо создаёт **только `data/demo.sqlite3`**: два вымышленных счёта, зарплату/аванс, аренду и шесть разных кредитов с обязательными платежами. Повторный запуск на заполненной базе отказывается что-либо менять. Для настоящего учёта используйте другую, изначально пустую базу `finance.sqlite3`.

Демонстрационный прогноз 18 октября — 30 ноября 2026: минимальный общий остаток 24 100 RUB, конец периода 125 900 RUB, разрыва нет. Это синтетический пример, не оценка финансов владельца.

## Что работает

- Счета в RUB, начальные остатки на конец заданной даты, фактические доходы/расходы, атомарные переводы без роста общего дохода/расхода.
- Разовые ожидания и ежемесячные правила (зарплата, аванс, обязательные платежи), конец месяца и февраль. Факт с `occurrence` закрывает ровно одно ожидание, даже при иной фактической дате/сумме.
- Прогноз по каждому дню и счёту, минимальный остаток, первая дата разрыва. Просроченные неподтверждённые расходы учитываются консервативно; просроченные ожидаемые доходы не становятся доступными деньгами. Расходы в один день считаются раньше доходов — без точного времени безопаснее не рассчитывать на порядок зачисления.
- Покупка как сценарий без записи расхода; настраиваемые резерв и ежедневный бюджет, который дополняет обязательства. До явной настройки бюджета модуль не отвечает `affordable=true`. Горизонт задаётся датами: для решения о покупке используйте конец следующего месяца и сравните базу со сценарием.
- Черновики текста/голоса/чеков, вопросы по неясным суммам и датам, подтверждение, точные и вероятные дубли, отмена с журналом причин. Записи не удаляются физически.
- Любое число кредитов, включая шесть: остаток, номинальная ставка, платёж, комиссии, следующая дата, оставшийся срок. Базовый график и досрочное погашение разовой/ежемесячной суммой, сокращение срока или пересчёт платежа. Все округления процентов — до копейки.
- Денежный календарь через `calendar`, устойчивый реестр Telegram-напоминаний с индивидуальным `lead_days`, резервная копия SQLite, CLI и MCP для Ива/будущих агентов.

## Границы первого этапа

Полный Ива на VPS не разворачивался и сейчас не требуется. Плагин/MCP сохранён, текущий Windows-адаптер использует то же ядро. Реальный Telegram voice и чтение пользовательского PDF/альбома проверены; статусы подтверждения импорта проверяются по базе.

Локальная речь: whisper.cpp; чтение изображений и сканированных PDF: настоящий Codex CLI --image. Неясные суммы/даты не выдумываются. Цифровой график Альфа проверяется также строгим табличным парсером.

Модель кредита — номинальная годовая ставка / 12, месячное начисление, фиксированный платёж/комиссия. Дневные проценты, страхование, просрочки и особые правила банка не моделируются. Срок в режиме `term` определяется введённым платежом; `remaining_months` применяется для пересчёта платежа. Нужна сверка с банковским графиком. Условия кредита не создают платёж в календаре автоматически — отдельно добавьте `schedule`, как сделано в демо. Совокупная стратегия «лавина/снежный ком» для общего бюджета шести кредитов пока не реализована; доступны сравнения каждого кредита.

Подтверждение в MCP — доверенный вызов Ива после ответа владельца. Проверка личности находится на входе Telegram в Ива; отдельной подписанной кнопки подтверждения в модуле нет. MCP должен оставаться локальным. База не шифруется этим приложением: права ОС и шифрование диска/бэкапов настраиваются на VPS. Только RUB; мультивалютность не подменяется сложением разных валют.

Голосовые ответы подключены: Windows ru-RU TTS → ffmpeg → OGG/Opus → sendVoice. /voice auto, /voice on, /voice off; текст для проверки финансов сохраняется. Старый универсальный voice_reply.py оставлен для отдельной интеграции с полным Ива.

Поиск работы hh.ru, тендеры и закупки не подключены: механизмов пользователя в проекте нет. Модуль не содержит банковских API, покупок или платёжных команд.
